# Traps by topic

Lessons folded in from the lessons inbox, by the section of `../SKILL.md` they belong to.

## Safety on a shared worktree
- **`git rebase --continue` can fail with `update_ref failed for ref 'refs/heads/main': is at X but expected Y`** when another local session advanced the branch mid-rebase. `git rebase --abort` (reflog keeps your commits), confirm the blocking commit is real with `git cat-file -t <sha>`, then `git merge-base --is-ancestor HEAD <sha> && git merge --ff-only <sha>` to restore it losslessly before retrying the pull-rebase.
- **A move done as copy-then-delete leaves the old path deleted-on-disk but still tracked, silently, until someone looks.** After any claimed move or retirement, `git status` the OLD path (or use `git mv` so both sides stage together) and commit the deletions with the new files.
- **A textual 3-way merge or rebase of concurrently edited code can silently drop a closing brace.** Build (and run the checks) after EVERY rebase or cherry-pick of source, not only after a clean merge; the post-rebase build is the catcher, not a formality.
- **A push into a repo (to create refs) can trigger `git gc --auto` there**; on a slow mount its `reflog expire --all` ran ~100 s. Pass `-c gc.auto=0` on any push or ref write into a repo you are only draining.
- **In zsh, `git show $c:path/file` fails with "bad substitution" or silently mangles**: `:s`, `:h`, `:t` after a variable are history modifiers. Brace it, `git show "${c}:path"`. A loop piping this into `sha256sum` prints the empty-input hash `e3b0c442...` for every file, which reads like real, identical results.
- **`git ls-files --deleted` lists only files still in the INDEX but missing from the worktree**; a `git rm` (staged delete) has left the index and is invisible there. Also ask `git diff --cached --no-renames --name-only --diff-filter=D`. `git log --diff-filter=D` misses moves unless `--no-renames`.
- **A hook or script asking whether a file is "already tracked" must compare against HEAD, not the index.** `git ls-files` reads the INDEX, so a file staged a moment ago counts as tracked; use `git ls-tree --name-only -z HEAD`.
- **A clone's `.git/index` mtime is not evidence of work**: any read-only `git status` (another agent's sweep, or the checker itself) refreshes it. To judge whether a clone is active, use the mtimes of `.git/HEAD` and `.git/logs/HEAD`, plus `git status --porcelain` for dirty work, and set `GIT_OPTIONAL_LOCKS=0` on every read-only call so the check does not touch the lock or index.
- **`git rev-parse --verify --quiet <prefix>^{commit}` on an AMBIGUOUS short sha exits 1 with EMPTY stderr**, indistinguishable from "no such commit", so code that treats exit 1 as absent fails open. To tell them apart, drop `--quiet` and parse stderr (`ambiguous` vs `Needed a single revision`).
- **A clone you did not create is attacker input.** `git archive`/`diff`/`show` honour replace refs, grafts, in-tree `export-ignore`/`export-subst` and repo-config diff drivers/`fsmonitor`, so a harness that tests "sha X" through git can be shown another tree. Use `GIT_NO_REPLACE_OBJECTS=1`, `GIT_GRAFT_FILE=/dev/null`, `-c core.fsmonitor=false -c diff.external= --no-ext-diff --no-textconv`, and export via `ls-tree` + `cat-file`, not `archive`.
- **A test that drives git at a fake http server must pin `credential.helper=` and `GIT_TERMINAL_PROMPT=0`.** A global helper that is a desktop credential manager pops a login dialog on the owner's screen on a 401 (three orphaned dialogs).
- **For "which of these names exist at <sha>" use ONE `git grep -o -h -I -P '\b(?:a|b|c)\b' <sha>`, not many `-F -e` patterns.** On a 38.8k-file tree with 9 identifiers `-F -w -o` took 45 s, `-l -w -F` 3.7 s, `-q` per name ~1.6 s each (no early-exit win), and the single PCRE alternation 1.7 s for all names.
- **A CLI flag that names commits must resolve each value to exactly one commit (`git rev-parse --verify`), never prefix-match.** `c.startswith('')` is True, so a `--superseded "$SHA"` flag with `SHA` unset waved every unlanded local commit through.
- **An unclean shutdown can leave NUL bytes in git metadata files** (`objects/info/alternates`, `.git` gitdir files); `os.path.realpath` raises `ValueError` on them and killed a reaper timer. Any reader of git metadata must treat a NUL line as unreadable (fail closed), not crash.
- **A refused `git fetch` rewrites `.git/FETCH_HEAD`, so its mtime is not the last good fetch.** Date that from `.git/logs/refs/remotes/origin/main`, which moves only when the ref moves.
- **Dirt in a deploy checkout whose every path equals an origin blob is a half-done `git pull`, not a writer; an interrupted pull can also die after writing the index.** A `pull --ff-only` that dies rc 128 after 'Updating files 7/7' leaves HEAD unmoved and every later run refusing 'local changes'; the dirt is STAGED (renames too) and matches an intermediate commit in `HEAD..origin/main`, not the tip, because the next fetch moves origin on. A 'landed dirt' check must compare against every commit in that range, index and worktree both, put such paths back and retry; read the unit's journal before hunting a writer.
- **`GIT_LITERAL_PATHSPECS=1` in the environment of a git call that runs hooks (commit, push) leaks into the hooks.** A hook's own glob pathspec (`git ls-files -- '*.html'`) then matches nothing and the guard silently passes. Use `:(literal)` path prefixes on hook-running calls instead.
- **`GIT_ALTERNATE_OBJECT_DIRECTORIES` pointing a sha256 repo at a sha1 repo's objects** makes `git log` print 'wrong index v2 file size in <lender>/objects/pack/...' and 'commit-graph hash version 1 does not match version 2'. It reads as a corrupt lender pack but the lender is sound: check the borrower's `git rev-parse --show-object-format` before blaming the pack.
- **A git-reading function fed repo-root paths must run from the toplevel:** pathspecs and blame resolve against the cwd, so an empty diff looks like 'git cannot say', and a fixture run at the repo root passes while every real caller in a subdirectory fails. After a fix pinned by fixtures, replay the real row that filed it.

## Filesystem operations beat git plumbing
- **A read/write round-trip of a CRLF-tracked file rewrites every line to LF** (a 7-word fix showed as a 1150-line diff). Check `file <path>` or `git diff --stat` before committing; edit such files in bytes (`open(p,'rb')`) or with `newline=''`.
- **A local `git clone <path>` HARDLINKS the object files**, so `chmod -R a-w` (or `u+w`) on the new clone rewrites the mode bits of the SOURCE repo's objects too (same inodes). For a read-only pinned copy use `--no-hardlinks` (a 14 GB repo: ~1 min) or clone from the remote.

## Auditing existing code
- **Branch churn by `git diff --numstat` (added+deleted over net) cannot tell a loop rewriting its own code from a loop deleting inherited code.** One file read 10.3x gross/net, yet `git blame` at the tip showed all 84 loop-added lines survive and the 102 deletions were the base branch's lines. Measure survival with blame before calling a file 'rewritten'.

## Batch
- **Search many names with ONE `git grep -o -w -F -e name1 -e name2 ...` and count in Python, never one `git grep` per name.** A per-name loop over a branch tree for 1,300 names ran past 10 minutes and was killed; the single call finished in under 100 s.
